# Design specification schema

Read this reference when creating or updating a run-level `design-spec.yaml`.

## Required groups

### `design`

- `name`: stable run/device identifier.
- `top_cell`: valid GDS top-cell name.
- `mode`: `new`, `live-edit`, or `legacy-migration`.
- `dbu_um`: database unit in micrometres. It must be fine enough to represent the strictest coordinate tolerance while retaining sufficient coordinate range.
- `source_intent`: short description of the sketch, KLayout selection id, or source layout.

### `layers`

Each logical layer maps to `[layer, datatype]`. Required mask text belongs on its SiN 1/y or metal 10/0 layer. Reserve separate helper layers only for non-delivery markers. `export.allowlist` must explicitly name logical layers.

### `process` and change scope

For this user's SiN designs the template selects `profile: sin-user-process`. Set `exposure_groups` to a list of `{id, writefield_size_um}` entries. `resolve_process_defaults()` resolves each group's layers and optical-interface defaults, verifies consistent inside/outside/total narrow lengths and fills a missing SiN tessellation limit. A single group can fill null logical layers; an explicit conflicting layer fails rather than being silently rewritten. Fixed UV/metal layers are checked for every group count.

For multiple groups, every exposure-dependent logical layer declares ownership in `process.layer_exposure_groups`, mapping its name to a group id. Declare custom logical aliases in `process.layer_roles`, e.g. `device_large: sin`; existing names such as `device` cannot be reinterpreted to bypass their role. Undeclared aliases on process mask layer numbers fail. Keep complete feature ownership in the project manifest, including annotations and overhanging tapers. `port_overrides` are recorded and checked; actual geometry is generated by the project driver. The included single-device generator explicitly rejects multi-group inputs even if the generic resolver can resolve their mappings.

Use explicit `width_reference` and `gap_reference` (`top` or `bottom`) when sidewalls make the distinction relevant. Record `device_kind` (`single` or `array`) and sourced pad-component profile. Declare pair rotation and common-slot ownership separately. Keep a single current scan table behind geometry/labels/manifests.

For a local change declare `change_scope.editable`, `.preserved`, `.recompute`. For example changing a lead may require new resistance labels, but must preserve pad-local geometry and other mask layers. This is an edit contract, not authorization to alter unrelated items.

### `unit_cell`

- `family`: component family such as `microring`, `disk`, `racetrack`, `spiral`, or `custom`.
- `source`: `project-library`, `legacy`, `klayout-selection`, or `new`.
- `parameters`: component-specific numbers with unit-bearing names such as `radius_um` and `width_um`.
- `tessellation`: geometry approximation contract. `midpoint_chord_deviation_nm` is an upper bound on a middle vertex's distance to the line through its two neighbours. The user SiN profile resolves it to 0.1 nm and requires strictly less after read-back, on both mask boundaries, not just the centerline.

### `waveguide`

- `width_um`, `coupling_gap_um`, and `coupling_length_um` define the straight cavity-coupling section.
- `route_kind`: use `euler-edge-transition` when the central straight bus connects to displaced edge straights through Euler bends.
- `euler`: contains the minimum radius and requested minimum sampling density for each bend. The reference validator raises `points_per_90_deg` as required by the three-point bound, width and DBU; the resolved report retains both requested and actual values.
- `left_edge` and `right_edge`: contain the edge-straight lengths and vertical offsets from the coupling bus.

### `ports`

Every port has a unique `name`, a `role`, and an orientation convention. Generated coordinates may be omitted from the input form and written into the verification report.

### `verification`

Declare requested numeric tolerances and checks. A check that lacks process data must not be silently promoted into a process DRC.

### `export`

- `working_gds`: optional layout retaining helper layers.
- `clean_gds`: delivery layout.
- `allowlist`: logical layers allowed into the clean file.

## Units

Use micrometres for geometry and degrees for angles. Encode units in field names. Convert to nanometres only in reports where it makes the requested tolerance easier to read.

## Circular tessellation

For radius `R` and `N` equal angular segments, the vertex-to-two-neighbour line distance is:

```text
s = R * (1 - cos(2*pi/N))
```

The single-segment arc sagitta is instead `R*(1-cos(pi/N))`; do not substitute it for the three-point rule (approximately a factor of four difference for fine sampling).

For an upper limit choose **ceil**, not nearest integer, and check the result. Use the outer boundary radius for a circular strip and the same angular stations for both boundaries. Reserve coordinate quantization error before choosing N: the reference generator subtracts `sqrt(2)*dbu_um*1000` nm from the target. Measure the **maximum** three-point distance on saved coordinates and require it below the target; a mean near 0.1 nm is not sufficient. If very fine sampling collapses points at the DBU, adjust precision/range or report the conflict.

SiN smooth curves use uniformly distributed centerline arc-length stations (equal angles on circles), with enough resolution for the highest curvature and offset boundaries. Keep true corners/endpoints as semantic boundaries, not curve samples. Other layers use about 1 µm curve point spacing per user convention. Do not add meaningless points to straight lines/rectangles. Never omit small-curvature or transition regions in a way that creates long chords or distorted offsets. Fragment using common station indices for both sides; inspect width, curvature, seams and long chords after export.

For the reference Euler route, `|r_h''(s)| <= k*(1+h*k)+h*|k'|` bounds the acceleration of either offset boundary at half-width h. A three-point distance at equal s intervals is bounded by `max|r_h''|*ds²/2`. The solver reserves quantization margin and an additional integration/junction allowance before deriving a minimum even station count. The user's point count is a lower bound, not permission to use a coarse curve. Half-width ≥ minimum bend radius is refused because its offset can fold.

The generator writes semantic ring/route cells and uses shared-station fragments, avoiding overlong polygon records. Read-back merges only internal route seams, requires one connected hole-free strip and exact terminal caps, then tests **all smooth saved boundary triples**, including straight/curve junctions and points next to fragment boundaries. Only the four verified terminal corners are excluded; long edges, small curvature or a coarse bend cannot exempt a point. A failed maximum check leaves the current delivery intact and reports the rejected candidate. A PATH route beyond the supported XY record count is refused with guidance to use polygon delivery. Custom project curves still need their own semantic boundary checks; this generator does not provide a complete process DRC.

### Source and scope

`DUV 700nm氮化硅设计指南.pdf`, page 7, graphical instructions under “如何判断图形分辨率合理？” define three adjacent points A/C/B, line AB and the perpendicular from C, and say its length should be “0.1 nm左右为宜”. The user's clarification makes **<0.1 nm** the SiN acceptance bound. The document's general DUV statement of no writing fields does not override the user's separate EBL field rules. Uniform sampling and other-layer ~1 µm spacing are user conventions, not numeric thresholds inferred from this PDF. Read diagram text as well as extracted text when consulting the source; the defining text here is embedded in an image.

The supplied old R=200 µm synthetic example is a regression case, not a second source of process limits. Record the applicable profile/source and any stricter user override in each run.
