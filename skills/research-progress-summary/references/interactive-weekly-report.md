# 离线交互周报

## 正式交付物

周总结的正式成品默认是一个单文件离线 HTML。CSS、绘图库、交互脚本、报告所需数据和文字全部内嵌；断网后直接从本地文件打开仍须完整工作，不依赖 CDN、远程字体、在线 API 或本地服务器。

当周目录默认包含正式 `report.html` 和过程资产 `assets/weekly-report-wireframe.<ext>`。草图归入当周过程资产，正式报告保持一份 `report.html`。除草图外，默认不额外生成 PDF、PNG 或其他静态副本；只有用户另行明确要求时才生成附加格式，并先确认用途和输出位置。所有输出、中间产物和缓存都写入项目允许的本机目录，不能写入任何只读证据源。

## 图表设计

新建或重绘数据图时调用 `scientific-plotting` Skill，按已确认方案落实科学问题、权威数据源、原始/处理数据边界、单位、不确定性和显示尺寸。图表说明复用讨论结果与来源信息，融入图旁细节即可。默认视图直接呈现主结论和必要数值；额外控件按实际阅读需求选择。

所有数据图默认允许放大、缩小、拖动、选中数据点并查看数值。必要的数值和主结论必须在默认视图中可见，不能只藏在悬停提示里。图例筛选或选择状态不得改变原始数据；如果为了性能需要抽样、聚合或降采样，必须在讨论阶段说明并获得用户确认，精确数值仍从声明的权威原始数据计算。

遵守科研绘图规则：坐标、单位、原始数据、拟合、平滑、理论值和不确定性明确区分；不能从视觉上方便的平滑曲线提取未经说明的精确结论。图表在正常浏览器缩放下即可阅读，不靠用户放大页面来弥补过小字体。

## 克制表达与可编辑文字

报告以图和证据为主。每张数据图默认只附一句直接结论，结论句本身使用高对比黑色粗体，不显示“一句话结论”“结论”或同类标题前缀。来源、方法、限制、异常和冲突放在就近的可展开区域中。概览、阻塞和下周重点也优先使用短句，不重复图中已经表达的信息。

结论句直接陈述当前状态、证据边界或待验证项。需要校准表达时拆成两个独立事实句，减少否定式对照和修辞转折。深色模式下使用对应的高对比前景色，保持与浅色模式黑色粗体相同的强调层级。

正式页面不得保留草图中的占位提示、内容取舍说明或防误解文案。正文只呈现实际动作、观察、证据、判断和行动，不为页面中缺少的内容添加“未纳入”“不包含”“不涉及”一类声明。证据边界用正向范围表达，例如写明判断实际采用的日期、样本、数据集和核验状态。若数据剔除是会影响复现或解释的真实分析步骤，将其依据、规则和影响放入方法或来源细节。

概览、图结论、问题/阻塞、待确认事项和下周重点等叙述区域应可直接编辑，数据、图形编码和来源元数据默认只读。页面提供明确的“进入/退出编辑”和“保存编辑副本”操作：保存时把当前文字序列化进新的自包含 HTML 并下载，不覆盖原始证据或未经确认的旧周报。

正文编辑后记录编辑时间。文字润色直接保存；涉及数字、完成状态或科研判断的修改，核对对应来源后更新相关结论。复核范围限于受影响内容，页面以简洁的编辑时间记录修订。

## 延续上期风格

在绘制草图前，打开并实际检查紧邻上期正式周报，优先复用：

- 信息层级、章节顺序和页面宽度；
- 字体层级、间距、颜色角色和图表尺寸；
- 结论位置、来源呈现和交互控件习惯；
- 整体信息密度和桌面端阅读节奏。

科研真实性、可读性、离线性和可访问性高于机械复刻。如果上期设计遮挡数据、字号过小、颜色难以区分或缺少必要交互，先在讨论和草图中指出并获得用户确认，再做最小必要调整。找不到上期周报时明确说明，并先提出基线草图供确认。

## 轻量交付检查

Codex 受控浏览器可能拒绝直接导航到本地 `file://` 页面。不要绕过该限制，也不要把拒绝访问误判为 HTML 损坏。浏览器验收时，从对应的当周周报目录启动一个仅绑定 `127.0.0.1` 的临时 HTTP 服务，通过 `http://127.0.0.1:<port>/assets/weekly-report-wireframe.html` 打开草图，通过 `http://127.0.0.1:<port>/report.html` 打开正式周报；使用空闲端口，不向服务目录写入任何内容，验收结束后立即停止服务。最终交付物仍是可离线打开的单文件 HTML，不依赖该临时服务。

正式 HTML 生成后，默认集中做一轮检查：

1. 打开实际页面，通览默认桌面视图，确认正文和图表显示完整、字号可读；结合资源引用确认所需代码和数据已内嵌。
2. 对本期新增或改动的交互实现选一张代表图，试用缩放、拖动、选点与数值显示；同一实现复用于多张图时，复用功能检查结果。文字编辑与保存逻辑首次使用或发生改动时，试改一句并确认保存副本重开后保留文字且图表正常。
3. 结合资料整理结果核对新增或改动的数字、状态和结论来源；通过后即可交付。

检查以发现实际交付问题为目的。常规周报采用上述轻量流程；全量逐图交互遍历、多屏幕尺寸与多浏览器测试、网络隔离测试、自动化测试脚本、截图和独立审计报告，仅在用户明确要求或具体异常确需定位时按需开展。科研图生成阶段已完成的数值与单位核对直接复用，周报阶段聚焦嵌入后的显示和交互。

发现问题时修复并复查受影响部分。例如沿用上期绘图组件、只更换数据时，核对新数据和页面显示即可；新增选点联动时，补查联动涉及的图和数值。浏览器受限时说明实际检查范围和待用户查看的项目，交付可查看的文件，不将未执行的检查声称为通过。数据错误、内容缺失或核心交互失效等已知问题解决后再作为完成版交付。
